containerアプリはパスではなくホスト全体を占有するため、他のアプリと同じFQDNは使えません。 FQDNを空欄にすると、このポート・TLSの扱い(Traefik経由の443番)による外部公開はなくなります (🖥️コンソールからのみ操作する計算専用コンテナ向け。その場合このポートもServiceも作成されません)。 下の「追加の公開ポート」はFQDN/ポートの設定と関係なく使えるため、 例えばVPNのように443番でのTraefik経由の公開が不要なアプリは、 ここを空欄にしたまま追加ポートだけを設定することもできます。

素の python・node 等は既定のコマンドがすぐ終了して再起動を繰り返すため、 sleep infinity など起動し続けるコマンドの指定が必要な場合があります (スペース区切り)。

容量上限はなく (ノードのディスク容量に依存)、ホスト側の実体は /data/containers/{{ form_name or '<name>' }}/ です。 レプリカ数2以上は全レプリカが同じストレージを共有するため、同時書き込みに対応しないアプリは1のままにしてください。

サイドカーコンテナ (任意)

同じPod内で追加のコンテナを一緒に動かせます。WordPress+MySQLのような「連携する複数コンテナ」を1つのアプリとしてデプロイする場合に使ってください。 同じPod内のコンテナ同士は localhost で通信できます (例: MySQLサイドカーには 127.0.0.1:3306 で接続)。 レプリカ数は1のままにしてください — 2以上にするとサイドカーもレプリカごとに個別に立ち上がってしまい、データベース等は正しく共有されません。

Deployment と Service の生YAMLを直接編集します (env変数・複数コンテナ・command指定など自由に書けます)。 privileged・hostNetwork・管理外のhostPath等は拒否されます。 spinapp-ui.dev/app ラベルは消さないでください(消すと一覧・削除・コンソールがこのアプリを認識できなくなります)。

「終端」は/configのHTTP/HTTPS設定に従い (現在: {% if traefik_scheme == 'https' %}HTTPS{% else %}HTTP{% endif %})、認証・アクセスログ分析が使えます。 「パススルー」は常に443番でTLSを復号せずコンテナへ転送します (証明書はコンテナ側で用意、認証・ログ分析は不可)。 {% if not container_passthrough_enabled %}パススルーモードは/configで無効化されています。{% endif %}

コンテナ自身が生成するHTML内に古いhttp://絶対URL（CSS/JS/画像など）が残っていて、HTTPSページ上でブラウザに 「混在コンテンツ」としてブロックされる場合の応急処置です。有効にすると、ブラウザに対して http://のサブリソース要求を送信前に自動的にhttps://へ書き換えるよう指示するレスポンスヘッダーを追加します (根本的にはアプリ側の設定・保存データをhttps://に直すのが望ましいです)。「終端」モードのみで有効です。

追加の公開ポート (任意)

上のポート・TLSの扱いとは別に、TCP/UDPのポートを追加でそのまま公開できます。 「転送先」は空欄なら外部ポートと同じ番号としてコンテナへ転送されます。 外部ポートとコンテナが実際にリッスンしているポートが異なる場合のみ入力してください。 Traefikを経由しないため、FQDNによる絞り込みもTLS終端も一切行われません。 指定したポートは誰からでも到達可能になります。信頼できる用途にのみ使用してください。
